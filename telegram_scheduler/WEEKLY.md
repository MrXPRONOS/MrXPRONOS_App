# Weekly promotional scheduling (experimental, not yet live)

The weekly batch imports existing source-of-truth promo content, images and approval allowlists for XPVIP, day-based offers, bookmaker bonuses and guides. It does not fabricate campaigns or create new advertising copy. The Sunday 13:30 UTC/Togo execution prepares Monday-Sunday posting slots: XPVIP 07:00, day offers 06:00, bonuses 07:30, guides 08:00. Each authorized pair of channels gets its own queue entries.

The bot platform cannot natively schedule: a personal Telethon session is used only if explicitly enabled. In-message Telegram bot inline keyboards are NOT preserved. Instead the original HTTPS links appear in image captions. Telegram message scheduling, message delivery, audience targeting, account permissions and compliance with promotion terms must be verified on a private test channel before live activation.

Required production gates: TG_SCHEDULER_WEEKLY_ENABLED=true, TG_SCHEDULER_ENABLED=1, TG_SCHEDULER_ACCOUNT_ID, TG_SCHEDULER_ALLOWED_PEERS (two numeric IDs), both existing TELEGRAM_CHAT_ID/TELEGRAM_CHAT_ID_SECONDARY secrets as matching marked IDs, existing Telegram personal credentials, Supabase secrets. Never enable while any legacy personal Telegram client can overlap. Existing cron-job.org triggers for the four source workflows are NOT modified until replacement has proven successful; no duplicate public posts should be created. Missing approvals abort the weekly batch rather than silently losing approved days.

Preview manually via workflow_dispatch mode=preview. The weekly execution is disabled by default. The manifest is an ephemeral artifact of the GitHub job and is never committed. Static offers can expire or change: verify each Sunday before scheduling. A media image must stay under repository root and be a nonempty real file. An uncertain Telegram result stops the batch and requires manual reconciliation. Workflow deployment into main is a separate activation gate.
